# PicoBoi frontend

A buildless chat page with the trained Picoboi-100K model running in a browser worker. No inference server, third-party runtime, analytics, or persistent conversation storage is used. Serve over HTTPS or localhost for worker loading and checksum verification.

## Preview

From the repository root:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory web/dist
```

Open http://localhost:4173. Once the status says On device, try Find the ball, Count apples, or Fix a sentence. Replies stream from the worker. New chat clears history and cancels outstanding generation.

## Inference

- `dist/models/picoboi-100k-v1/`: actual FP32 checkpoint weights, tensor manifest, tokenizer.
- `dist/inference.js`: causal transformer, per-stage KV caches, RMSNorm, RoPE, SwiGLU, tied embeddings, greedy decoding.
- `dist/model-worker.js`: same-origin loading, SHA-256 verification, generation and cancellation.
- `dist/normalize.js`: browser-local greeting aliases, contraction expansion, curated spelling fixes, and conservative edit-distance suggestions.
- `dist/project-replies.js`: narrowly matched creator questions with a fixed attribution link, handled separately from model inference.
- `dist/web-lookup.js`: direct Wikipedia searches and plain-text reference excerpts for unfamiliar terms.
- `dist/app.js`: chat state, streamed replies, web lookup, errors, model status, and navigation.

Weights contain 99,120 learned parameters in 396,480 raw bytes. `training/export_browser.py` exports them from the trained checkpoint. Model answers are not corrected after generation. Creator questions such as `who made you?` receive the built-in project reply `I was made by @farilyaz.` with a link to https://twitter.com/farilyaz. This reply is UI content, not evidence of learned model ability. The whole creator exchange is excluded from model history so its handle cannot become unsupported input on a later model turn. All other supported prompts use the trained model. Unfamiliar terms can trigger the Wikipedia fallback described below. Application notices are separate from model output.

Before tokenization, user input goes through a deterministic normalizer. Whole greetings such as `yo`, `hi`, and `whats up` become `hello.`. Contractions expand, common typos are corrected, and explicit aliases map to supported words. The user sees the original input plus an `I read that as:` notice for rewrites. Successful normalized input is retained in model history. Model output is never normalized. Other recognized words retain their tense and form; negation is preserved. Broad one-edit spelling matches are suggestions, not automatic guesses. Unlisted names, synonyms, and ambiguous abbreviations such as `ur` remain outside the model vocabulary; web lookup may find a reference, but ambiguous queries can match the wrong topic. Bare ambiguous forms such as `its`, `were`, and `well` are not treated as contractions.

The tokenizer still supports the same 800 word forms plus 12 punctuation/structural tokens. The checkpoint, tokenizer IDs, and corpus have not changed. Unsupported words trigger a Wikipedia lookup when enabled; other unsupported digits and characters receive a notice. Context includes history and generated output. At least 32 tokens are reserved for an answer; older complete conversation pairs are omitted as needed, with a notice. Oversized messages are rejected. Replies stop on a learned turn/EOS token or length/context limits. The normalizer improves input tolerance; it does not improve the model's underlying greeting skills, eliminate ambiguity, or reduce its weight size. Contraction expansion can increase token count.

## Web lookup

The checked **Look up unfamiliar topics** option automatically searches English Wikipedia when the worker reports words outside its fixed vocabulary. Greetings, supported prompts, and creator replies stay local. Switching the option off restores vocabulary notices with no web lookup. Normalization still fixes known typos before deciding whether a lookup is needed.

The page extracts keywords from the original message, searches Wikipedia's public MediaWiki API with CORS enabled, and requests plain-text introductory extracts for up to three results. If nothing matches, it retries the unfamiliar terms once. The highest-ranked nonempty excerpt streams into chat with source links and a reference label; the additional links are related search matches. This is retrieved reference text, not a new answer generated by the 100K model. It may not answer a specific question, and it is not a general web scraper, live-news search, or permanent learning mechanism.

Search terms are sent to Wikipedia, without cookies or a referrer. The toggle, help text, About page, and footer explain this. No chat history is sent with a lookup. Excerpts render as text, never executable HTML, and source links are constructed on the Wikipedia domain. Web exchanges are excluded from model history because their words may not tokenize. Requests have a 12-second deadline; New chat aborts the request and discards stale answers. Network failures and no-match results produce notices.

## Verification

```sh
.venv/bin/python training/export_browser.py
node training/tests/browser-inference.mjs
node training/tests/normalize-input.mjs
node training/tests/web-lookup.mjs
```

Fixtures contain PyTorch logits and greedy answers. Tests check numerical agreement, the binary checksum, vocabulary rejection, context trimming, and cancellation/reuse. Browser checks cover real generation, follow-up questions, unsupported words, and New chat. See the model card for capability limits. This implementation uses JavaScript/CPU and does not promise offline page loading after the tab closes. Model inference stays local. When web lookup is enabled, extracted search terms are sent to Wikipedia; conversation history is not sent to an inference service.

## ASCII video background

The chat page has a same-origin, muted, 16-second ASCII jellyfish video loop. The source is credited to NOAA Ocean Exploration, Gulf of Mexico 2018; see `dist/media/CREDITS.md` for source links and processing details. The 18.5 MB source is transformed offline into a 572 KB WebM and a 917 KB H.264 fallback; the browser chooses one. `tools/render_ascii_background.py` rebuilds the assets with greyscale, contrast, pixelation, glyph rendering, seamless timing, and compression.

`dist/ambient-background.js` loads video sources only when motion is allowed. Reduced-motion and data-saver preferences receive a still poster. The pause/play button is keyboard accessible. The video pauses when the tab is hidden or the About page is open; active chats soften the background to preserve text readability. A failed video or blocked autoplay leaves a still image. No remote video requests, canvas rendering, or animation dependencies are needed at runtime.
